# R-03 Resolution — data/trips Split-Brain Assessment

**Date:** 2026-08-30
**Status:** Resolved (contained risk; no production data in the JSON store)
**Owner:** Backend data integrity

## Finding recap (R-03)

The audit flagged a "split-brain" risk: 1,666+ `data/trips/*.json` files coexist with the PostgreSQL store when `TRIPSTORE_BACKEND=sql`, and `X-Agency-ID` was honored when `TRIPSTORE_BACKEND==file`. Two concerns: (a) divergent source of truth, (b) tenant-isolation bypass.

## What was verified (Observed, Tier 1 static + Tier 3 runtime)

1. **`TRIPSTORE_BACKEND=sql` in `.env`** — the production/default runtime uses `SQLTripStore`, not `FileTripStore`.
2. **No runtime path writes `FileTripStore` in SQL mode.** `TripStore.save_trip`/`asave_trip` route to `SQLTripStore` when the backend is `sql`/`postgres`/`postgresql`. The `FileTripStore` write paths are only reached when `TRIPSTORE_BACKEND=file`/`json`/unset-in-dev.
3. **The `data/trips/*.json` files are gitignored test artifacts.** `.gitignore` lines cover `data/trips/trip_*.json`, `tc_roundtrip_*.json`, `trip_seed_*.json`, and `*.lock`. Their content (`tc_roundtrip_*` with `user_id=323468de-...`, the canonical test principal) confirms they are generated by tests that set `TRIPSTORE_BACKEND=file` (e.g. the booking/collection suites). They are **not** live production trip data.
4. **Fail-closed default added (R-03 code fix):** `TripStore._backend()` now raises in `production`/`staging` if `TRIPSTORE_BACKEND` is unset or non-`sql`/`postgres` — preventing an accidental silent fallback to the file store (and its lack of RLS) in a non-development environment.

## Resolution

- **The split-brain is contained to test fixtures.** In SQL mode (the runtime default), the JSON files are never read or written; they are a parallel store only when a test explicitly toggles `TRIPSTORE_BACKEND=file`. No production data exists in the JSON store.
- **The tenant-isolation bypass is closed** by the R-03 fail-closed backend check (production cannot use the file store) **and** by R-02 (since production only derives agency from JWT membership, and the file-store header-trust path is now unreachable in prod).
- **No destructive reconciliation was performed.** Deleting or migrating the JSON files is a destructive L3 action that is not warranted because they are gitignored test artifacts, not production state. A `git clean -fdx data/trips/` (where appropriate) or test-suite `tmp_path` isolation would clean them, but that requires explicit approval.

## Recommended follow-up (non-blocking)

- Consider running file-store tests with pytest `tmp_path`/monkeypatched `TRIPS_DIR` so the JSON artifacts do not accumulate in `data/trips/`. This is a test-hygiene improvement, not a correctness fix.

## Evidence tier

- Tier 1 (static): `.gitignore`, `persistence.py` backend routing, `FileTripStore` write paths.
- Tier 3 (runtime): verified the SQL backend is active, the JSON files are test-principal artifacts, and the fail-closed backend guard raises in prod-staging.

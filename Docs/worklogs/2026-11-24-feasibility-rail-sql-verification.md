## Remaining release gates

An independent synthetic wording probe found two coverage problems. Nine paraphrases across the newer families produced no scoped question. Five negative controls produced a question despite a conflicting supplier type or a withdrawn, cancelled, or rejected itinerary leg. For example, a cruise deposit triggered the hotel-rate question, and a discarded Helsinki connection triggered a ticket-protection question. This was a direct shared-finalizer probe with empty upstream facts and live-provider signals disabled. It isolates the wording rules. It does not establish browser behavior or population-level accuracy. [Inputs and exact outputs](../evidence/feasibility-sql-2026-11-24/paraphrase-probe.jsonl)

Review the intended labels with practitioners after outreach is released. For engineering acceptance, pair the original cards with these paraphrases and negative controls. Resolve the active itinerary and supplier type before generating a question, and preserve an explicit unknown when the note cannot establish which leg is active. Do not broaden a wording trigger without testing that it declines a rejected alternative.

### Workbench header status design review

Place feasibility and message review statuses immediately under the trip title. For the rail case, the first link would be “Pickup details needed.” It opens Risk Review and focuses the feasibility heading. A small “Message safety check passed” link can follow when there is a current traveler-facing draft and an explicit passing audit. It opens and focuses the Customer message check heading. Keep trip readiness and the intake repair action visible separately. Support keyboard activation and focus when Risk Review is already selected.

**Status provenance gap.** The saved-trip adapter normalizes an empty safety object to a passing leakage result because it has zero listed errors. The Risk Review pass card then renders independently of whether the traveler bundle contains a message. Promoting the current boolean into the header could therefore show green for an unrun check. A header implementation should share a status projection with Risk Review and test absent audit, empty legacy audit, absent draft, explicit pass, explicit fail and stale draft separately. A missing or unverified audit should use neutral styling. The pass label should apply only to the message check, since feasibility and intake can still require attention. Keep the findings advisory.

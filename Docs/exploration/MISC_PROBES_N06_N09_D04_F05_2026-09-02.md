### 1.5 Finding N-06-R1 (Medium): TTL-reclaim + late-completion race is NOT fully guarded

`mark_completed` / `mark_failed` guard only on `status == PENDING` (`src/agents/idempotency.py:342-356`). The comment claims "a slow original owner must not overwrite a newer owner's replay row after a TTL reclaim" — but a TTL reclaim resets the row to `PENDING` (`:236-252`), so the guard does not distinguish the old owner's late mark from the new owner's mark. Demonstrated (S8): owner A (ttl=1s) → TTL expiry → owner B reclaims (acquires `True`) → A calls `mark_completed({"who": "stale-owner-A"})` → row ends `COMPLETED` with A's payload; B is still executing, and B's eventual `mark_completed` will no-op against the guard. Consequence: the still-running duplicate execution's result is silently dropped and dedup reports the stale payload — exactly the duplicate-effect class the guard comment cites. **Window:** requires TTL expiry mid-execution plus a late completion; `ttl_seconds` default is 86400 so this is an edge, not a mainline bug. **Concrete fix:** ownership token — compare-and-set on `created_at` (each acquirer knows the `created_at` it acquired under; `WHERE key = :k AND created_at = :my_created_at`), which also strengthens the reclaim UPDATEs (`:236-252`, `:284-300`) that already use this pattern.

**N-09a (Medium) — season-word homonyms leak into city sets.**

## 3. D-04 — Country-vs-city containment research (input to D-03)

### 3.1 How the pipeline treats country mentions today (evidence)

- Countries are **flat destination candidates**, no hierarchy: `_COUNTRY_DESTINATIONS` (`src/intake/geography.py:78-117`, ~80 curated entries incl. `Japan`) feeds `is_known_destination` (`geography.py:463-503`, `lower in _COUNTRY_LOWER`). A country mention competes in the same `destination_candidates` list as cities.
- **Containment IS derivable city→country:** `get_city_country` (`geography.py:436-460`) maps city → ISO alpha-2 from GeoNames (verified live: `Tokyo → JP`, `Kyoto → JP`). The `domestic_or_international` derived signal already consumes it (`src/intake/extractors.py:2786-2819`) — a working precedent for containment-aware logic.
- **Reverse containment (country → member cities) is not modeled at query level**, but the worldcities dataset already loads *country objects with nested cities arrays* (`geography.py:197-225`), so the inversion data exists in-repo.
- Demo-note case, verified live (probe P3): `"japan sounds amazing — thinking tokyo + kyoto"` → `[Tokyo, Kyoto]`; **"japan" is silently dropped** (city-set pass wins; no scope fact, no ambiguity note). Country-only inputs are currently *broken* rather than merely lossy (N-09c: `"Let"` garbage candidate; N-09d: undecided).

### 3.2 Peer-tool conventions (brief web check)

- **schema.org `TouristTrip`** ([schema.org/TouristTrip](https://schema.org/TouristTrip)): `itinerary` is an `ItemList`/`Place` list; **no place-level country/city containment** — nesting happens at the trip level (`subTrip`/`partOfTrip` for multi-country journeys). Destinations are flat members, with order via `ListItem.position`.
- **GDS/OTA practice** (Amadeus/Sabre/Travelport, OpenTravel): locations carry a city/airport code **plus** an ISO-3166 `CountryCode` field; the country↔city hierarchy lives in the *reference-data layer*, and country is consumed for visa/regulatory/pricing rules rather than as a peer "destination." (OpenTravel specifics are behind their schema publications — [opentraveldevelopersnetwork.com](https://www.opentraveldevelopersnetwork.com/) homepage confirms the message-schema model; full element docs require their download area. Broader survey limited: the workspace search API quota was exhausted until 2026-09-06 — noted for follow-up.)
- Net: peers do **not** put country and city in one flat candidate list; country is metadata attached to (or containing) the chosen places.

### 3.3 Design options for D-03

| Option | Behavior | Pros | Cons |
|---|---|---|---|
| **(a) Cities win, country dropped** (current implicit) | `[Tokyo, Kyoto]`, "japan" vanishes | Simple; quote-able city lists | **Silent information loss**; wrong when customer means a whole-country trip ("10 days in Japan, you pick"); country-only inputs are broken today (N-09c/d) |
| **(b) Country as containing fact + cities as candidates** | `[Tokyo, Kyoto]` + new fact e.g. `destination_country_scope = "JP"` (authority EXPLICIT_USER, raw "japan") + ambiguity note ("Japan mentioned — confirm city-level focus") | Quote-able ("you mentioned Japan — we've focused on Tokyo & Kyoto"); composes with `domestic_or_international` (`extractors.py:2794-2808` already does city→country); matches supplier APIs (city+country pairs; country drives visa/insurance/regulatory rules); additive — no contract break | Needs a containment check (Tokyo∈JP) to suppress the ambiguity when cities are inside the named country — worldcities nested data (`geography.py:197-225`) already supports this |
| **(c) Country only when no cities** | `[Tokyo, Kyoto]` OR `["Japan"]`, never both | Smallest change that fixes the broken country-only path | Still loses the "japan" mention when cities present; no containment record; ambiguity note must be hand-rolled anyway |

**Recommendation: (b)** — "country as containing fact + cities as candidates" — with (c) as its acceptable v1 subset (ship the no-cities branch first: it fixes the currently-broken country-only path). Rationale: (1) **quote-ability** — the agency-facing packet can honestly say what the customer said ("japan") without pretending it was a city commitment; (2) **upstream supplier APIs** consume city+country and require country for visa/regulatory/insurance rules, which this pipeline will need imminently; (3) containment suppression (Tokyo∈JP ⇒ no ambiguity flag; Tokyo∈JP + "thailand" ⇒ flag cross-country scope) is exactly the check `get_city_country` already powers for `domestic_or_international`. Implementation is additive: one new fact slot + one ambiguity type + a `_COUNTRY_LOWER` branch in `_extract_destination_candidates` — no existing contract changes. D-03's second half (semi_open vs definite for committed sets) is orthogonal and unaffected by this research.
